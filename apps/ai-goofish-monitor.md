# AI Goofish Monitor

- 上游项目：https://github.com/Usagi-org/ai-goofish-monitor （MIT）
- 作用：根据自然语言需求建立闲鱼监控任务，按预算、包邮、地区等条件筛选；结合图片和卖家信息作AI初筛；通过已配置的通知渠道推送，保留监控价格记录。
- 这是本地网页服务，不是双击启动的桌面客户端。默认访问地址 `http://127.0.0.1:8000`。
- 代码免费开源，模型接口费用由所选服务决定。AI仅辅助筛选，不保证捡漏、真假或卖家可靠性；成交前自行核验，遵守平台协议和请求频率，不绕过验证码或风控。

## 先说明并取得同意

需要 Docker（Windows/macOS 通常用 Docker Desktop）、本地磁盘空间，以及用户自己的看图模型接口、闲鱼登录状态和通知配置。已有 Docker 则复用；安装新环境、需要管理员权限或启动容器前先说明，不静默安装。

## 安装和配置

1. 从上游仓库取得项目，或读取上游 README 的 Docker 部署说明，使用官方镜像 `ghcr.io/usagi-org/ai-goofish:latest`。
2. 将 `.env.example` 复制为本机项目目录的 `.env`，只在本机填写：`OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL_NAME`。模型必须支持图片输入。由用户提供接口信息，不读取其它应用的凭据，不将 `.env` 上传到 GitHub 或远程机器。
3. 配置独立的 `WEB_USERNAME`、高强度 `WEB_PASSWORD`，不要保留上游公开的默认密码。口令和API Key不写进日志或回复。
4. 只绑定本机：将官方 `docker-compose.yaml` 中 `8000:8000` 的映射设为 `127.0.0.1:8000:8000`；默认使用 `restart: "no"`，不创建系统服务或开机自启。确需公网访问/常驻服务时另行取得明确授权。
5. 在项目目录执行 `docker compose up -d`。只处理本项目容器，不停止、删除其它业务服务。
6. 打开本地地址，让用户自己完成闲鱼登录以及 README 要求的登录状态导入；不要收集密码，不绕过安全验证。通知使用用户选择的 ntfy、Bark、企业微信或Webhook等渠道，通知凭据同样只保存在本机。

## 首次验证与交付

- 本地页面可访问并能登录；在“任务管理”用一个代表性需求建立任务，用户可先选关键词判断，AI模式需自己的模型配置完成。
- 必须如实区分“服务已运行”和“账号/模型/通知均已配置、任务已验证”，不能把装好页面说成已经全天自动监控。
- 告诉用户项目位置、本地网址、启动/停止方法和仍需本人完成的步骤，不在回复里暴露模型Key、登录状态JSON或密码。
- 停止本项目：在项目目录执行 `docker compose stop`；保留数据卷和用户配置，不擅自清空。
