# 任务拆解排期词

执行前读取仓库根目录 README.md 的「任务执行规则」，并遵守全部安全边界；读取失败先停下说明。

## 输入

项目目标、截止日期和每天可用时间。缺少影响结果的信息先问用户。

## 执行步骤

1. 先核对买家提供的项目目标、可用工时与截止时间，提醒把敏感公司名、人名或金额换成代号。
2. 按里程碑倒推、每天具体任务、依赖卡点标注、缓冲时间预留4个模块写出完整排期提示词。
3. 附上一个原创示例项目拆解，标出每天不超过3件核心任务的要求，排除只写空泛口号的做法。
4. 按买家的输入直接跑出一份可执行排期初稿，并附每周复盘调整指令与自查标准。

## 产出

task-breakdown-schedule-prompts.md：任务拆解排期指令模板、风险预留规则和一份按输入生成的排期表。写入用户指定的新输出目录，文件重名时另起名，不覆盖原件。

## 验收

指令含4个排期模块，并按买家输入产出带缓冲的排期初稿。

最终报告实际生成的文件路径、检查结果、未完成项及限制。没有生成或没有验证的内容不能写成已完成。
